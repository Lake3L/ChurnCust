# Churn Scoring Platform

> Сервис скоринга оттока, который решает не «кто уйдёт», а **«кому звонить, чтобы заработать»**: откалиброванные вероятности + порог, выведенный из unit-экономики.

**Статус: в разработке.**

## Проблема

Телеком-оператор теряет клиентов: в датасете IBM Telco ~27% абонентов уходят. Удержание дешевле привлечения, но кампания удержания не бесплатна: каждый звонок с предложением скидки стоит денег, а конверсия удержания далека от 100%.

Наивные решения не работают в обе стороны. «Звонить всем» — сжигание бюджета: большинство клиентов и так не собирались уходить, а скидку получат все. «Не звонить никому» — молчаливая потеря маржи с каждым ушедшим. Классическая ML-постановка «предскажи отток и отсеки по 0.5» тоже не работает: порог 0.5 никак не связан с экономикой кампании.

Этот проект строит полный производственный контур вокруг простой модели: порог решения выводится из экономики (V, C, p), вероятности калибруются (иначе экономический порог бессмыслен), сервис отдаёт готовое бизнес-решение «звонить / не звонить», а мониторинг замечает, когда данные «поехали».

## Правила проекта

- Отложенный test set (20%) не трогается до финальной оценки. Все решения принимаются на valid.
- Одна и та же функция построения фичей используется в обучении и в API (защита от train/serve skew).
- Данные — под DVC, в git не попадают.
